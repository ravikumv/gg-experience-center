Classic GGSCI vs Admin Client vs Web UI vs REST API

Four ways to administer Oracle GoldenGate, spanning two architecture generations. GGSCI belongs to the classic architecture; Admin Client, the deployment console Web UI, and the REST API all belong to the Microservices architecture (which is what OCI GoldenGate deployments use).

Dimension Classic GGSCI Admin Client (CLI) Deployment Console (Web UI) REST API
ArchitectureClassic ArchitectureMicroservices ArchitectureMicroservices ArchitectureMicroservices Architecture
Interface typeLocal command-line shell on the GoldenGate hostCommand-line client connecting over HTTPS to the Administration ServiceBrowser-based UI served by the deploymentHTTPS JSON endpoints exposed by each microservice
Where it runsOn the GoldenGate install directory of the source/target hostOn a consultant's workstation or a bastion/jump host, connecting remotelyAny browser with network access to the deploymentAny HTTP client — scripts, orchestration tools, monitoring platforms
AuthenticationOS-level access to the host; optional GGSCI-level passwordDeployment admin username/password or credential store alias over TLSDeployment admin username/password over TLSBasic Auth / token over TLS, same identity as the console
Typical use in OCI GoldenGateNot used — OCI GoldenGate deployments are Microservices onlyScriptable administration, batch changes, CI/CD-style automation, this simulator's command engineDay-to-day monitoring, quick start/stop actions, visual topology, exploring a deployment interactivelyBuilding custom dashboards, integrating with ticketing/monitoring systems, programmatic bulk operations
Command styleGGSCI> info allAdminClient> INFO ALL (same command grammar, different transport)Point-and-click; underlying calls are RESTGET /services/v2/extracts style JSON calls
Scripting / automationOS shell scripts wrapping ggsci << EOF blocksNative — commands can be scripted/piped, ideal for repeatable change scriptsLimited — not designed for scriptingBest fit for automation — language-agnostic, used by the Web UI itself under the hood
Pros
  • Familiar to long-time GoldenGate admins
  • Works fully offline/local
  • Full command surface, same grammar as GGSCI
  • Good for remote, repeatable administration
  • No browser required
  • Visual topology and health at a glance
  • Low learning curve for new team members
  • Fully programmatic
  • Powers custom dashboards and integrations
  • Language/tool agnostic
Cons
  • Not available on OCI GoldenGate deployments
  • Requires host-level access
  • Command-line only, no visual topology
  • Not scriptable
  • Slower for bulk/repetitive changes
  • Requires JSON/HTTP tooling knowledge
  • No interactive command help built in
Rule of thumb Ravi applies with customers: GGSCI is the on-prem, classic-architecture tool and is not how OCI GoldenGate deployments are administered. For OCI GoldenGate, use the deployment console Web UI for day-to-day visual monitoring, Admin Client for scripted/remote changes, and the REST API for integration and automation — all three ultimately talk to the same underlying microservices.
