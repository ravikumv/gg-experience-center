Purpose of HUB

Consolidates capture and delivery for many source/target pairs into one managed deployment, rather than standing up separate GoldenGate instances per pair.

When to Use HUB

Multiple sources feeding one or more targets, multiple targets fed from one or more sources, or when centralized monitoring/lifecycle management across many replication pairs is a priority.

Benefits

Centralized monitoring, simplified patching/upgrade cadence, shared credential store and security policy, and a single operational surface instead of many scattered installs.

Prerequisites

Sufficient host sizing for concurrent Extract/Replicat processes, network reachability to every source and target, and a naming convention that scales as pairs are added.

Network Requirements

The HUB host needs outbound connectivity to every source and target database, and inbound access from any distribution/receiver paths crossing a WAN or cloud boundary.

Sizing Considerations

CPU, memory, and disk (for trail files) scale with the number of concurrent Extract/Replicat processes and aggregate transaction volume, not with the number of source/target pairs alone.

Centralized Management

One Service Manager (or a small HA pair) governs multiple Deployments, each hosting the Extract/Replicat processes for a given pair or group of pairs.

Monitoring

A single pane of glass for lag, throughput, and process health across every replication pair, instead of per-instance monitoring stitched together after the fact.

HA / DR Considerations

Because many pairs depend on one HUB, HA/DR planning for the HUB itself (standby Service Manager, replicated configuration, trail directory protection) becomes more critical than in a single-pair deployment.
