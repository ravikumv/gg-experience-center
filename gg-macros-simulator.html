What is a GoldenGate Macro?

A GoldenGate macro is a named, reusable block of GoldenGate parameter-file syntax. Define it once using DEFINE MACRO #name, give it optional parameters, and CALL it inside any TABLE or MAP statement. At process startup GoldenGate expands every CALL in-place — pure text substitution before any execution begins.

Think of macros as managed copy-paste with parameters: write once, call for every table, one change propagates everywhere instantly.

Core benefit — Without macros: 4 audit columns × 80 tables = 320 lines of COLMAP repeated 80 times. With one #audit_cols macro: 80 CALL statements. Change the macro body once — all 80 tables update instantly.

How to use macros — 5 steps

1
Create dirprm/gg_macros.macWrite all your DEFINE MACRO blocks in one shared file.
2
INCLUDE it in your .prm fileAdd INCLUDE ./dirprm/gg_macros.mac before any CALL statements.
3
CALL the macro in TABLE / MAPArguments are positional — must match PARAMS count exactly.
4
VIEW PARAMS to verifyRun VIEW PARAMS <groupname> in GGSCI to see the fully expanded file.
5
Nest macros if neededA macro body can CALL another macro (no recursion allowed).

Macro syntax — every part explained



  

    
Do's

      
DEFINE before CALL — macro must be defined/INCLUDEd before its first CALL.

      
Use & for params — without it, text is literal, not substituted.

      
END; needs a semicolon — omitting it is a startup parse error.

      
VIEW PARAMS to debug — shows the fully expanded parameter file.

    

    
Don'ts

      
No recursion — a macro cannot CALL itself.

      
No runtime logic — macros expand at startup only.

      
Arg count must match — mismatch is a startup error.

      
No $ or : prefix — parameters always use &.

Integrated Extract
Registers with Oracle 19c's LogMiner server. Reads LCRs from redo logs without touching data blocks.

    
Macro expansion
Happens at process startup — text substitution before any TABLE or MAP is processed.

    
FORMAT RELEASE 12.3+
Required on EXTTRAIL for full column metadata needed by Parallel Replicat and Oracle 26ai vector columns.

    
Non-Integrated Parallel Replicat
Applies DML directly via OCI without Oracle's apply server — ideal for 26ai and heterogeneous lakehouse targets.
